# מומנטום יומי — מערכת איתור נקודות כניסה

מערכת שרצה בענן (לא על המחשב שלך) ומאתרת מדי יום תרחישי מומנטום ברמה יומית, לפי אותה
מתודולוגיית Wave A / Wave B שבנית ב-RKY MON — רק על נרות יומיים במקום תוך-יומי, ועל
אוניברסת S&P 500 + Nasdaq-100 שלמה במקום מניה אחת בכל פעם. משלבת גם את רשימת המעקב
הפונדמנטלית שבנית בהייפ.

**עלות: $0/חודש.** אין שרת שרץ 24/7 — הכל בענן חינמי: GitHub Actions מריץ את הסריקה
פעם ביום, Supabase/Neon שומרים את הנתונים, ו-Vercel/Cloudflare Pages מארחים את האתר.

## מה בפנים

```
scanner/waveDetector.js    זיהוי Wave A/B יומי + VWAP מעוגן (פורט מ-momentum_wave.pine)
scanner/dataFetch.js       שליפת נרות יומיים מ-Yahoo Finance (פורט מ-MONEY/server.js)
scanner/fundamentals.js    פונדמנטלס: Finviz + SEC EDGAR + stockanalysis.com (פורט מ-HYPE)
scanner/updateUniverse.js  מעדכן את רשימת S&P500+Nasdaq100 מ-Wikipedia (רץ פעם בשבוע)
scanner/run.js             נקודת הכניסה של הסריקה היומית
scanner/db.js              עטיפת Postgres
db/schema.sql              סכמת ה-DB - להריץ פעם אחת
.github/workflows/         שני ה-cron jobs (סריקה יומית + עדכון אוניברסה שבועי)
api/                       Serverless functions ל-Vercel (נתונים לפרונט, רשימת מעקב, רענון ידני)
web/index.html             הפרונט-אנד - עברית RTL
```

## הקמה — פעם אחת

### 1. DB: Supabase או Neon (בחר אחד, שניהם חינמיים)

1. הרשם ב-[supabase.com](https://supabase.com) (או [neon.tech](https://neon.tech)) עם חשבון GitHub.
2. צור פרויקט חדש (שם: `momentum-scanner`, כל אזור).
3. פתח את ה-**SQL Editor** והדבק את כל התוכן של `db/schema.sql`, הרץ.
4. מצא את מחרוזת החיבור (**Connection string**, בסופאבייס תחת Project Settings → Database;
   ב-Neon מוצג ישר בדשבורד). היא נראית כך:
   `postgres://postgres:PASSWORD@HOST:5432/postgres`
   שמור אותה בצד — זה ה-`DATABASE_URL`.

### 2. GitHub: הריפו + ה-Actions

1. צור ריפו חדש (פרטי) ב-GitHub, למשל `momentum-scanner`.
2. העלה אליו את כל התיקייה הזו (`git init`, `git add .`, `git commit`, `git push`).
3. בריפו: **Settings → Secrets and variables → Actions → New repository secret**, הוסף:
   - `DATABASE_URL` — המחרוזת מהשלב הקודם
   - `SEC_USER_AGENT` — השם והמייל שלך (כמו שהגדרת ב-`config.json` של הייפ), למשל
     `Ron <your-email@example.com>` — נדרש ע"י SEC EDGAR.
4. עבור ל-**Actions** בריפו, ותפעיל פעם אחת ידנית (**Run workflow**):
   - קודם: **Update Scan Universe** (ממלא את טבלת ה-tickers, ~600 מניות)
   - אחר כך: **Daily Momentum Scan** (הסריקה הראשונה — עלולה לקחת 15-25 דקות)
5. משם והלאה זה רץ לבד: עדכון אוניברסה כל יום שני, סריקה כל יום אחרי סגירת ארה"ב.

### 3. פרונט-אנד: Vercel

1. הרשם ב-[vercel.com](https://vercel.com) עם GitHub.
2. **Add New Project** → בחר את הריפו `momentum-scanner`.
3. הגדרות הפרויקט → **Environment Variables**, הוסף:
   - `DATABASE_URL` — אותה מחרוזת
   - `SEC_USER_AGENT` — אותו ערך
   - `GITHUB_TOKEN` — טוקן גישה אישי ל-GitHub (Settings → Developer settings →
     Personal access tokens → Fine-grained, הרשאת `Actions: Read and write` על הריפו הזה
     בלבד) — נדרש רק כדי שכפתור "סרוק הכל עכשיו" יוכל להפעיל את ה-Action.
   - `GITHUB_REPO` — לדוגמה `ron-username/momentum-scanner`
4. **Deploy**. בסיום תקבל כתובת כמו `momentum-scanner.vercel.app` — זה האתר שלך, זמין
   מכל מקום (גם מהנייד).

זהו — המערכת פעילה. פתח את הכתובת, הוסף מניות לרשימת המעקב, ולחץ "סרוק הכל עכשיו" כדי
לוודא שהכל עובד לפני שתחכה להרצה האוטומטית הבאה.

## בדיקה מהירה שהכל עובד

1. פתח את האתר → אמור להופיע "עדיין לא בוצעה סריקה" אם עוד לא הרצת ידנית.
2. הוסף טיקר לרשימת המעקב (למשל `NUVB`) → הוא אמור להתרענן אוטומטית תוך כמה שניות
   ולהציג P/E ומחיר הוגן.
3. לחץ "סרוק הכל עכשיו" → תוך כמה דקות (בדוק ב-GitHub Actions שהריצה הסתיימה בהצלחה)
   רענן את העמוד → אמורים להופיע תרחישים תקפים בטבלת "מועמדים היום" (אם יש כאלה באותו יום).

## שני דברים חשובים שגיליתי תוך כדי בנייה

**1. VWAP מעוגן = תרחישים תקפים נדירים יותר מהצפוי.** ה-VWAP המעוגן מחושב מיום השיא
של Wave A קדימה. כשהשיא היה בנפח/מחיר גבוה, ה-VWAP הזה "נתקע" גבוה למשך כמה ימים, וקשה
לצאת מעליו מבלי לרדוף את המחיר (התנאי שסוגר את זה, `entryNotMissed`, לא נותן לרדוף יותר
מ-5% מעל הכניסה). בבדיקות סינתטיות שהרצתי זה יצר מצב שבו שתי הדרישות (מעל ה-VWAP המעוגן,
ולא רחוק מדי מהכניסה) כמעט סותרות זו את זו בתרחישים מסוימים. יכול להיות שכדאי לשקול
לעגן את ה-VWAP מנקודת שפל Wave B במקום משיא Wave A (זה יתן VWAP נמוך יותר, קרוב יותר
לאזור הכניסה בפועל) — לא שיניתי את זה כי זו הייתה ההחלטה המפורשת שלך, אבל שווה להסתכל
על זה אחרי כמה ימי סריקה אמיתיים ולראות אם יוצאים מעט מדי תרחישים.

**2. יעד ה-15% נשאר "שטוח" ולא משתדרג לרמה טכנית.** בזיכרון היה מתועד שרצית שהיעד
ישתדרג לרמה טכנית אמיתית כשקיימת (למשל שיא קודם) במקום 15% קבוע — אבל בקובץ ה-Pine
העדכני ביותר שמצאתי (`momentum_wave.pine`) הפיצ'ר הזה כבר לא קיים (כנראה הוסר באחד
משלבי הפישוט המתועדים). פורטתי בדיוק את מה שבקובץ בפועל (15% קבוע). אם תרצה להחזיר
את שדרוג היעד — זה שינוי ממוקד ב-`scanner/waveDetector.js`, תגיד ואוסיף.

## החלטות פתוחות (לא ננעלו — קל לשנות)

- **גודל האוניברסה**: כרגע S&P 500 + Nasdaq-100 (~600 מניות). סריקה יומית שלוקחת
  15-25 דקות ב-GitHub Actions (מגבלת 45 דקות בקונפיג). אם תרצה יותר (למשל Russell 1000),
  אפשר, אבל זמן הריצה יגדל בהתאם.
- **שכבת נרטיב Claude API**: לא נכללה (כמו שהחלטת בהייפ, כדי לא להוסיף עלות). אם תרצה
  להוסיף ניתוח תרחישים בעברית כמו ב-Moni — אפשר להוסיף כ-endpoint נפרד, בעלות שתלויה
  בשימוש.
- **אימות מול נתונים היסטוריים אמיתיים**: הרצתי רק בדיקות סינתטיות (`npm test`) כי
  לסביבת הפיתוח שלי אין גישה לאינטרנט של Yahoo Finance. מומלץ להריץ את ה-Action הראשונה
  ולבדוק כמה תרחישים יוצאים ביום רגיל, ולכייל אם צריך.
